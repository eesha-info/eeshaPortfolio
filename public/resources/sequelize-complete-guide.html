Promise-Based ORM for SQL

Sequelize Complete Guide

Sequelize is a mature, promise-based Object-Relational Mapper for Node.js that works across PostgreSQL, MySQL, MariaDB, SQLite, and SQL Server. It maps JavaScript model classes directly onto relational tables, generating the SQL for you while adding built-in validation, lifecycle hooks, and a declarative way to describe associations between tables. This doc walks through the 8 things a backend engineer actually needs to know to use Sequelize well in production — in the order you'll naturally run into them — with a diagram, a "where to use it" guide, and concrete implementation steps for every single one.

Diagram · From JS Models to a Running Database

Everything you write is a JS model; Sequelize translates it into the correct dialect's SQL and runs it against the actual database. Everything in the row below is what keeps that translation safe and predictable — schema changes go through migrations, relationships through associations, data integrity through validations and hooks, and multi-step writes through transactions.

hasOne / hasMany / belongsToMany at a glance

Diagram · The Three Association Types

hasOne adds a foreign key that points at a single related row; hasMany is the same foreign key, just on the "many" side; belongsToMany needs a real intermediate table (PostTag) holding a foreign key to each side, since neither Post nor Tag can hold a column referencing multiple rows on the other side.
