The Relational Query Language

SQL Complete Guide

SQL (Structured Query Language) is the standard query language behind every relational database — PostgreSQL, MySQL, SQL Server, and SQLite all speak the same fundamentals underneath their own extensions. Learn to select, filter, sort, join, and aggregate rows once, and that knowledge transfers almost unchanged to whichever engine you end up running in production. This doc walks through the 10 concepts a beginner actually needs, in the order you're likely to need them, with a diagram, a "where to use it" guide, and concrete implementation steps — including runnable SQL snippets — for every single one.

Diagram · What Happens When You Run a Query

Every query follows the same path: the text you write is parsed and handed to the query planner, which decides the fastest way to satisfy it (a full scan, or an index lookup); the storage engine then actually reads the tables (and any indexes) on disk or in memory, and hands back a result set — the rows your application actually sees.

Anatomy of a SELECT Statement — Written Order vs. Execution Order

This is the single most useful thing to internalize about SQL: the order you type the clauses is not the order the database evaluates them in.

Diagram · Logical Query Processing Order

You write SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY ... LIMIT, but the engine runs it starting from FROM and finishing near the end with the column list in SELECT — which is exactly why a column alias defined in SELECT can be used in ORDER BY (evaluated after) but not in WHERE (evaluated before SELECT has run at all).
