Backend & Cloud Engineering

AWS Backend & DevOps Learning Roadmap

Amazon Web Services (AWS) is a collection of on-demand cloud computing services — compute, storage, databases, networking, and automation — that you rent instead of buying and racking physical servers. Instead of provisioning a machine, plugging in a cable, and installing an OS, you request an EC2 instance and it exists seconds later, billed by the second. This doc walks through the 25 AWS and DevOps services a backend engineer actually needs, in the order you're likely to need them, with a diagram, a "where to use it" guide, and step-by-step implementation instructions for every single one.

Key Backend Pattern — Decoupling Slow Work

The single most useful pattern on this whole roadmap: never make a client wait on work it doesn't need to wait on.

Diagram · Client → API → SQS → Worker → External Service

The API's only job is to validate the request, drop a message on the queue, and respond — step ① happens in milliseconds, before the real work even starts. The worker pulls from the queue on its own schedule (②③) and only then calls out to a slow external service (④). If that external service is down or slow, the client never notices — it already got its response.
